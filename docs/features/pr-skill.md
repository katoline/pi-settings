# pr スキル

## 概要

作業が完了して検証が通ったら、目的ごとにコミットし、作業ブランチを push して PR を作る（既存の PR は説明を作り直して更新する）手順。マージはしない。

## 関連

- コード：`agent/skills/pr/SKILL.md`
- 決定：[003](../decisions/003-auto-pr-and-merge-policy.md)
- 置き換え予定：[plan/phase-5-pr-tools.md](../plan/phase-5-pr-tools.md)（専用ツール `harness_pr_create` に置き換えて削除）

## 手順（要約）

1. 検証：プロジェクトの `AGENTS.md` / `CLAUDE.md` の検証コマンドを通す。無ければ「未検証」と PR 本文に書く。挙動に関わる変更なら独立レビューが済んでいることを確かめる
2. 現状把握：未コミットの変更・秘密ファイルの有無・既定ブランチ・既存の PR。マージ済みの PR しかないブランチなら、最新の既定ブランチから切り直す
3. ブランチ：既定ブランチ上なら作業ブランチを作る
4. コミット：1 コミット 1 目的。ファイル単位で分け、土台から順にコミットする
5. push と PR：`gh pr create`。既存の PR があれば `gh pr edit` で全体を作り直す（ユーザーが書いた記述は残す）
6. 報告：PR の URL・ブランチ・コミット一覧・検証結果

## しないこと

- マージ（依頼されたときだけ。ハーネスのガードが確認ダイアログを出す）
- force push・`--no-verify`・既定ブランチへの commit / push・リモートブランチの削除（ハーネスのガードが止める）
- `--amend` などの履歴の書き換え（明示的な指示があるときだけ）
