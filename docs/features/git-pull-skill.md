# git-pull スキル

## 概要

`/skill:git-pull` で起動し、カレントディレクトリのリポジトリ（リポジトリの外なら配下 3 階層までのすべて）をデフォルトブランチに切り替えて fast-forward で取り込む。作業中のブランチから切り替わるため、モデルが自動で使うことはない（`disable-model-invocation: true`）。

## 関連

- コード：`agent/skills/git-pull/SKILL.md`（手順）、`pull.sh`（本体）
- 移植元：Claude Code 用の `seino914/dotfiles` の `.claude/skills/git-pull`（2026-11-22 に移植。`pull.sh` は同一）

## 挙動

- 対象：カレントディレクトリが git リポジトリならそれだけ。そうでなければ配下（3 階層まで）のリポジトリすべて。見つけたリポジトリの内側（入れ子）と `node_modules`・シンボリックリンクは見ない。ホームディレクトリとその上位では実行を拒否する
- 各リポジトリで：デフォルトブランチ（`origin/HEAD`、無ければ origin の `main` / `master`）を求め、fetch し、切り替えて `git merge --ff-only origin/<デフォルトブランチ>` で取り込む。rebase はしない
- スキップ：detached HEAD・デフォルトブランチが分からない・追跡ファイルに未コミットの変更がある
- 失敗：fetch・切り替え・取り込みの失敗は git のエラーを添えて出す。切り替えた後なら元のブランチへ戻し、戻せたかも出す
- 出力：1 リポジトリ 1 行。`✓` 更新・`=` 既に最新・`-` スキップ／失敗。切り替えたときは `feature/x → main` のように元のブランチ名も出す
- 認証のプロンプトでは止まらない（`GIT_TERMINAL_PROMPT=0`）

## pi 向けに変えた点（移植元との違い）

- `${CLAUDE_SKILL_DIR}` の代わりに「このスキルのディレクトリ」と書く（pi はスキルの場所をモデルに伝える）
- `allowed-tools` を外した（pi では実験的な機能のため）。bash ツールの `timeout` は付けない（pi は秒単位で、既定では時間切れにならない）
- PR を作らないことを明記した（グローバル指示の「完了したら PR」と混ざらないように）

## 既知の制約

- 切り替えや取り込みで .gitignore 対象のファイル（手元の `.env` など）が上書きされないかの事前確認はしない
- 取り込み計画のフェーズ 1 のガード（既定ブランチ上での `git merge` を拒否）は、スクリプトの中のコマンドまでは見ないので、このスキルは止まらない（`bash pull.sh` として実行されるため）

## 確認したこと（2026-11-22）

- 使い捨てのクローンで、作業ブランチ → デフォルトブランチへの切り替えと取り込み、親ディレクトリからの走査、未コミットの変更でのスキップ
