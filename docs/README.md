# docs

pi-settings の計画・決定事項・機能の仕様・設定の詳細をまとめる場所。AI が参照するときは、まずこのファイルで置き場所を見て、該当するファイルだけを読む。

## 構成

| ディレクトリ | 中身 | 読むとき |
| --- | --- | --- |
| [plan/](plan/README.md) | 取り込み計画（フェーズごとのタスク・完了条件・状態）と、音声入力の計画 | 次に何をするか、作業の範囲を知りたいとき |
| [decisions/](decisions/README.md) | 決定記録（何を・なぜ決めたか・却下した案） | 方針の理由を知りたいとき。方針と食い違う変更をする前 |
| [features/](features/README.md) | 今ある機能の仕様（挙動・処理・既知の制約・関連ファイル） | 機能を変更・調査するとき |
| [setup/](setup/README.md) | シンボリックリンク・設定ファイル・プロバイダーの認証など、環境の細部 | 環境を作る・直すとき |
| [reference/](reference/README.md) | 外部の調査結果（取り込み元のリポジトリ、pi の API の要点） | 実装の参考が要るとき |

## 書き方のルール

- 1 ファイル 1 テーマ。機能・フェーズ・決定ごとに分け、各ディレクトリの `README.md` を索引にする
- 各ファイルの先頭に「概要」（1〜3 行）と「関連」（関連するコード・他の docs）を置く
- コードを変えたら、対応する `features/` と `plan/` のタスクの状態を同じ PR で更新する
- 決定を変えるときは、既存の決定記録を書き換えず、新しい記録を足し、古い記録の状態を「置き換え済み（→ NNN）」にする
- 日付は絶対日付（例：2026-11-22）で書く
- 推測は「推測」、確認できていないことは「未確認」と明記する
