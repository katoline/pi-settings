# 007: GitHub のブランチ保護は pi に作らせない

- 日付: 2026-11-22
- 状態: 有効

## 背景

取り込み元は、初めての push の前に既定ブランチがルールセットで保護されているかを確かめ、なければ確認ダイアログのうえでルールセットを作る（`harness_ensure_protection`）。

## 決定

- pi はブランチ保護（ルールセット）を作らない
- 保護されていないリポジトリで PR を作ったときは、ツールの結果と完了報告で知らせるだけにして、作業は止めない

## 理由

- リポジトリの設定を変える操作は、ユーザーが自分で行いたい（ユーザーの判断）
- 初めての PR のたびに確認ダイアログが出るのを避けられる
- 既定ブランチへの push はガードでも止めている

## 却下した案

- 取り込み元どおり、確認ダイアログのうえで作る案
- `/protect` のようなコマンドで pi に作らせる案
