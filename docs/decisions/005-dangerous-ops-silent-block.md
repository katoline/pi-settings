# 005: 危ない操作は確認ダイアログを出さずに止め、必要ならユーザーが `!` で実行する

- 日付: 2026-11-22
- 状態: 有効

## 背景

取り込み元のガードは、次の操作を「許可制」にして確認ダイアログを出す。

- 変更や履歴を壊す git 操作：`reset --hard`・`clean`・`rebase`・`--amend`・`branch -D`・`stash drop` など
- プロジェクトの外に影響するインストール：`brew` / `apt`・`npm -g`・`nix profile`・`darwin-rebuild` / `home-manager switch` など
- 保護パス（dotfiles・`~/.pi/agent`）への書き込み

普段の作業中に確認ダイアログが出るのは避けたい。

## 決定

- これらは確認ダイアログを出さずに止める（拒否）
- 拒否の理由として、モデルに「必要ならユーザーに `!<コマンド>` で実行してもらうよう伝える」と返す
- ユーザーが pi の入力欄で `!` から始めて実行するコマンドは、ガードを通らずに実行される（`tool_call` ではなく `user_bash` イベントになるため。実装時に確認する）

## 理由

- ダイアログが出ないので作業が止まらない
- 本当に必要な危ない操作は、人が自分で打てば済む

## 却下した案

- 取り込み元どおり確認ダイアログを出す案：普段の作業でダイアログが出る
- マージと同じく、依頼文に該当する語があればダイアログを出す案：操作ごとの語の一覧（reset・rebase・install …）を保守することになる
