# 003: 作業ごとに PR を自動作成し、マージは依頼されたときだけ確認して行う

- 日付: 2026-11-22
- 状態: 有効

## 背景

pi には作業を最後まで任せたい。一方で、既定ブランチへの取り込み（マージ）は勝手にしてほしくない。普段の作業中に確認ダイアログが出るのも避けたい。

## 決定

- 作業が完了して検証が通ったら、pi は確認を求めずに作業ブランチで commit・push・PR 作成（既存 PR は説明を更新）まで進める
- PR のマージは自分からしない・提案しない
- ユーザーの入力に「マージ」「merge」があるときだけ、マージの前に確認ダイアログを出し、許可されたら実行する。依頼が無ければダイアログを出さずに止める
- 既定ブランチへの commit・push、force push、push での削除、`--no-verify` は常に止める

## 理由

- 依頼の無いマージを確認ダイアログで止める方式だと、普段の作業中にダイアログが出てしまう（ユーザーの要望で変更）
- 依頼の有無はユーザーの生の入力（`/skill:…` の展開前）で判定できる

## 却下した案

- 取り込み元（pi-coding-agent-settings）の「CI が通れば確認なしで自動マージ」：マージは人が決めたい
- 依頼の有無にかかわらず、マージには常に確認ダイアログを出す案：普段の作業でダイアログが出る

## 既知の制約

- 「マージはしないで」のような否定文でも語が含まれていればダイアログになる（拒否すれば実行されない）
- pi が聞き返し、ユーザーが「はい」とだけ答えると止まる。pi には聞き返さないよう指示している
