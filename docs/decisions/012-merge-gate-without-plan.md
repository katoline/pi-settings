# 012: 計画が無いときも確認ダイアログでマージを判断し、マージ後にブランチを消さない

- 日付: 2026-11-23
- 状態: 有効

## 背景

フェーズ 5 で、マージを専用ツール `harness_pr_merge` にした（[003](003-auto-pr-and-merge-policy.md)）。移植元のマージのゲートは「確定した計画があり、検証が最新で成功、必要ならレビューが承認済み、CI が成功」を満たさないとマージしない作りで、計画が無い実行（質問への回答だけの依頼、計画を作らない小さな作業、手で作った PR）や、CI が無いリポジトリではマージできなくなる。また、移植元は `gh pr merge` に `--delete-branch` を付けてブランチを消していた。

## 決定

- 計画が無いとき（確定した計画が無い、または PR のブランチが計画の作業ブランチではない）も、マージを止めない。確認ダイアログの本文に「検証・レビューの記録を確認できていません」と注意として出し、ユーザーが判断する
- CI が無いときも、止めずに注意として出す
- 止めるのは次のときだけ：CI が失敗、CI が実行中のまま上限時間（20 分）に達した、サブエージェント、UI が無い。CI の状態を取得できない（`gh pr checks` が「チェックが無い」以外の理由で失敗した）ときも止める。計画が確定済みで PR のブランチが今のブランチなら、移植元のゲート（検証が最新で成功・必要ならレビューが承認済みで最新・未着手と進行中の項目なし）も効かせて止める。ただし、計画の最後の項目が進行中のときは数えない（マージの項目は計画の最後に置き、`in_progress` にしてから `harness_pr_merge` を呼ぶため。数えると、計画にマージの項目があるとき必ず止まる）
- マージの依頼（入力の「マージ」「merge」）は、その実行の間（steer・followUp を含む）だけ有効にし、実行が終わったら消す。`/plan resume` で始めた実行（`input` を通らない）では `harness_pr_merge` を出さない。計画にマージの項目があっても、一時停止から再開したあとは、ユーザーがもう一度依頼する。003 の「依頼が無ければダイアログも出さない」に合わせ、安全側に倒した。依頼を数えたのに実行が始まらなかった（認証切れなど）ときに持ち越さないよう、`/plan resume` で再開するときにも依頼を戻す
- 確認ダイアログで拒否されたら、その実行の中では、`harness_pr_merge` を呼び直してもダイアログを出さずに止める（自律ループが呼び直して、ダイアログが繰り返し出ないように）。拒否の記録は、依頼と一緒に、実行の終わりと `/plan resume` で戻す。計画のマージの項目は、拒否・ゲートで止められたら `deferred` にして残りを進める
- マージ後にブランチを消さない（`gh pr merge <番号> --merge` に `--delete-branch` を付けない）。リモートのマージ済みブランチは GitHub Actions が消す。ローカルのブランチはユーザーが整理する

## 理由

- マージは、ユーザーが依頼したときだけ行い、毎回確認ダイアログで許可を取る（003）。計画や CI の有無を理由に止めると、ユーザーが自分で判断して依頼したマージまで通らなくなる。判断材料を本文に出せば足りる
- CI の失敗・実行中は、判断材料ではなく壊れた状態か未完了の状態なので止める。待っても終わらない場合は、上限時間で止めて理由を返す
- 計画があるときは、モデルの申告ではなく記録（検証・レビュー・項目）で確かめられるので、そのゲートを残す
- ブランチを消すと、マージ直後に同じブランチで続きの作業をする、取り込み結果を見直すといった操作に使えなくなる。リモートは Actions が消し、ローカルはユーザーが整理できる。ガードも push でのリモートブランチの削除を常に拒否しており、一貫する

## 却下した案

- 計画が無い・CI が無いときも止める（移植元どおり）：計画を作らない作業や CI の無いリポジトリでマージできない
- 計画が無いときは確認ダイアログも出さずにマージする：003 の「許可されたら実行」に反する
- `--delete-branch` を付ける（移植元どおり）：上の理由

## 既知の制約

- 一時停止から再開した計画では、マージの項目を進めるのに、ユーザーの再依頼が要る

- 注意はダイアログの本文に出すだけなので、ユーザーが読まずに許可すると、未検証の変更がマージされる
